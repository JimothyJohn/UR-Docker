Joint 5 carries a different serial series and newer selftest firmware than the other five joints, and the arm's factory kinematic calibration (calibration.conf, dated Apr 2022) predates the swap. The controller flags the mismatch on every boot.

What the service manual says

§ 5.2.12 — Dual Robot Calibration
"If a joint is replaced on a calibrated robot the calibration is no longer valid. Performing a Dual Robot Calibration after replacement of a joint allows the robot to continue in the production line without modifying waypoints in the robot program."
Service Handbook p. 54 · requires 2 same-size robots + Dual Robot Calibration Tooling (part no. 185500)
§ 5.2.11 — Zeroing of Joints
"When a joint has been replaced and verified, it may be necessary to zero the joint so that it is aligned with the rest of the robot arm… Automatically — Dual robot calibration — this is the recommended method… Manually — Access Expert mode and use a spirit level, to level the joint."
Service Handbook p. 50 · Wrist 3 zero position: tool connector pointing upward, two bolts in tool holes + spirit level
§ 5.2.13 — Program Correction by Key Waypoints
"…helps adjusting programs waypoints when a program is moved from an uncalibrated robot to another. The technique can also be used to make programs work after replacements of joints."
Service Handbook p. 54 · does not support Use-Joint-Angles move nodes — those need manual correction

Impact & recommendation

Cartesian (TCP) accuracy is degraded until the arm is recalibrated — joint-space moves are unaffected. This independently validates this repo's practice of shipping zero-kinematics URPs and emitting motion as raw URScript movej() script nodes rather than native MoveJ/Waypoint nodes. If this cell ever needs calibrated Cartesian precision (vision-guided picks, tight-tolerance placement), schedule a Dual Robot Calibration through your UR distributor; otherwise document the limitation and continue with joint-space teach poses.

What the service manual says

§ 6.3 — Using Support File
"Go to Log tab, insert a USB stick, and click on Support File… This backup requires around 1 Gb memory, please use a USB stick of 2 Gb or more capacity."
Service Handbook p. 89 · the Support File bundles logs + flight reports for UR Log Viewer
§ 6.4 — Using Magic Files
"URmagic log file — copies the entire log history file to USB stick. URmagic backup programs — copies all programs and installation files to USB stick."
Service Handbook p. 90 · download from universal-robots.com/support; large history files take up to two minutes

Impact & recommendation

Pull a Support File (or scp the flight reports off over SSH — faster from this workstation), then delete flightreports/*.zip and log_history.bak. That recovers ~65 MB and drops usage to roughly 83%. Longer term, make the Support File part of the biannual inspection so the archive exists before you need the space.

Both symptoms match failure modes already documented in this repo: MoveJ-node IK resolving through the active (non-flange) TCP, and Cartesian moves launched from near-singular poses.

What the service manual says

§ 7.6.1 — Protective Stop: Preventive Measures
"Protective stops are indications of issues, including program or production issues — not only safety issues. An application which results in daily protective stops is not designed correctly and needs to be modified… Protective stops must never be acknowledged and reset automatically."
Service Handbook p. 113–114 · auto-acknowledge/reset voids the warranty and masks fault detection
§ 7.2.7 — Flight Records
"This will open 6 new windows with real-time data graphs for the selected Flight Record. Each opened window contains data for the respective joint and the data of the exact moment of the fault… Position, Velocity, Acceleration, Current, Torque."
Service Handbook p. 99 · open the archived recordings in UR Log Viewer to see exactly what tripped on Aug 11

Impact & recommendation

Nothing is broken today — the current session is clean. But the pattern (IK failures + repeat C154A0) says programs on this cell are being authored through poses the kinematics can't serve. Keep motion in joint space near singular regions, movej to a dexterous pose before any movel, and open the archived flight recordings in UR Log Viewer before deleting them (F-02) if you want the root cause of the Aug 11 stops on record.

Bars are log-scaled — C171A12 outnumbers everything else 10:1. The history file stores codes without message text; to translate a code, open a Support File in the UR Log Viewer (§ 7.2.8 "Log Start" shows description, category, source and timestamp per entry) or search the code on the UR support site. C154A0 is the one verified fault-class here: protective stop from a near-singularity Cartesian move (see F-03). C0A0 entries are program state messages (pause/play), not faults. The C171/C303/C313 volume is dominated by info-level communication events logged at every session — worth a Log Viewer pass if you're curious, not a fire.
