UR-Docker

a whole robot, no robot required

A Docker-Compose'd PolyScope simulator for Universal Robots e-Series, plus urctl — a tiny toolkit that drives it the same way you'd drive a real controller. Power it on, move it, write programs, and watch it work — all from your laptop.

What's in the box

Three friendly pieces

❀
🐳

The simulator

URSim 5.12.5 (UR10, e-Series) in a container. Real PolyScope, real Dashboard & Primary interfaces — viewable in your browser.

🤖

The urctl toolkit

A dependency-free Python CLI + library that powers on, moves, and runs programs. The same code drives the sim and a real robot.

👁️

Perception

An optional vision package: turn a camera frame into detected blobs with estimated depth — the seam toward pick-and-place.

Chapter One

Start the simulator in three steps

✦
1

Clone & bring it up

You only need Docker. The first build pulls the URSim image, so give it a minute.

# clone and start the e-Series simulator
git clone https://github.com/Olympus-Controls/UR-Docker
cd UR-Docker
docker compose up -d --build
2

Open the pendant in your browser

PolyScope runs over noVNC. Open it at:

http://localhost:6080/vnc.html?host=localhost&port=6080
Heads up: always connect via localhost — not the IP printed in the container log. That address won't work from your host.
3

Wake the robot up

Set up the Python environment with uv, then cold-start the controller to RUNNING (power on + release brakes):

uv sync                        # create the .venv (installs urctl)
uv run urctl bring-up          # POWER_OFF → IDLE → RUNNING
uv run urctl state             # read robot state as JSON

That's it — you have a robot. 🎉

Chapter Two

Tell it where to go

❦

Every urctl command works against the simulator out of the box. Mutating moves are checked against a safety envelope (joint limits, speed caps, required state) before they reach the robot, and written to an audit log.

# move in joint space (radians) — always safe from any pose
uv run urctl move-joints 0 -1.57 0 -1.57 0 0
uv run urctl move-home --velocity 0.3

# nudge the tool +50 mm along base +Y (Cartesian, relative)
uv run urctl move-tcp 0 0.05 0 0 0 0 --relative

# load a sample program and play it
uv run urctl load MotionDemo && uv run urctl play

# preview & validate without sending anything to the robot
uv run urctl --dry-run move-joints 99 0 0 0 0 0

Prefer Python? The library sits on the same Robot facade:

from urctl import Robot, RobotConfig

robot = Robot()                         # localhost sim, or…
robot = Robot(RobotConfig(host="10.0.0.5"))   # a real robot
robot.bring_up()
robot.move_joints([0, -1.5708, 0, -1.5708, 0, 0])
print(robot.get_state())
There's also an MCP server (urctl-mcp) that exposes every capability as a tool, so an LLM agent — Claude included — can discover and drive the robot. See the README for the config.
Chapter Three

Point it at a real robot

✿

Nothing is hardcoded to localhost — it's just the default. Set one environment variable (or pass --host) and the exact same toolkit drives a physical e-Series controller at its IP address.

uv run urctl --host 10.0.0.5 state
UR_HOST=10.0.0.5 uv run urctl bring-up
VariableDefaultMeaning
UR_HOSTlocalhostController host or IP
UR_DASH_PORT29999Dashboard port
UR_PRIMARY_PORT30001Primary Client port
UR_TIMEOUT_S10Socket timeout (seconds)
UR_AUDIT_LOGunsetAppend a JSON-lines audit record per action
Treat the robot's network like a backplane. On real hardware these ports are unauthenticated. Keep the controller on an isolated network — the client-side safety envelope is a guard, not a substitute for the controller's own configured safety limits. Credentials (e.g. an SSH password for file transfer) are read from your environment, never stored in this repo. Copy .env.example to .env to set yours locally.
Chapter Four

Things it already knows how to do

❀

The programs/ folder ships ready-to-run samples — load any of them from the pendant, or stream them straight to the Primary interface:

🧭

InspectionBot

A guided, teach-by-prompt quality-inspection tour. Walk it to each station; it asks pass/fail and pulses a verdict.

📦

PickPlace

A basic pick-and-place cycle — grasp at one station, carry across, release at another, return home.

💃

Dance & MotionDemo

Non-interactive motion routines for proving the full cold-start-to-finished-program lifecycle.

Want to author your own? urctl guided builds a program interactively — the robot raises a Yes/No dialog on its own pendant for each step, and records what you approve. See CLAUDE.md for the deep how-to.
